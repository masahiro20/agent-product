# 現地写真 → 一式資料（解体・造成）

写真と住所だけで、解体屋さんがそのまま見積の叩き台に使え、造成屋さんが積算に入れるレベルの
**参考資料**を作る。寸法・高さ・数量はすべて「推定値（参考値）」として明示し、根拠を必ず残す。

出力（`jobs/<日付>_<物件名>/output/`）:
- `<slug>.pdf` … A3横の一式資料（表紙総括／土地概況／写真台帳／建物・数量推定／立面図4面／現況平面・解体範囲図／解体概算見積／造成計画平面図／造成計画断面図／造成概算見積／確認事項・出典）
- `<slug>_見積.xlsx` … 解体・造成の内訳（単価列を自社単価に書き換えると再計算）＋残置物リスト
- `<slug>_図面.dxf` … 立面図・造成計画平面（境界・擁壁・等高線・計画高/現況高）を CAD で開ける形で

## 手順

### 0. 受け取り
- 写真（チャット添付・ドライブ・フォルダ）と住所を受け取る。住所が無ければ「住所（地番可）があれば標高・ハザードを自動取得して精度が上がる」と一言だけ伝え、無くても進める。
- 作業フォルダ `jobs/<YYYYMMDD>_<物件名>/` を作り、写真をコピー。`examples/site.template.json` を `site.json` として置く。
- 写真が少なく精度が出ない場合は `references/photo_guide.md` の撮り方を案内（追加撮影はお願いベース。待たずに推定で先に出す）。

### 1. 写真を読む（最重要）
各写真を Read で必ず見て、次を拾う。数値は**基準物からの比例**で出し、根拠を `measure_basis` と写真の `marks[].basis` に書く。
- 基準物: メジャー・スタッフ > ブロック（1段0.2m／1枚0.39m）> 玄関ドア高2.0m > 手すり1.1m > アルミサッシ幅1.69m > 外階段1段0.18〜0.2m（標準寸法は `data/demolition_unit_prices.json` の `standard_dimensions_m`）
- 建物: 構造（木造/軽量鉄骨/重量鉄骨/RC）、階数、外形（桁行×梁間）、1FL/2FL/軒高/最高高さ、屋根形状・勾配・材質、開口の位置と寸法、外階段・廊下・バルコニー、推定築年（仕様から）
- 戸数・間取り: 玄関ドア・メーター・室外機・郵便受けの数、間口（1Kなら≒3.64m）から
- 外構: ブロック塀（段数×長さ→㎡）、フェンス（m）、門扉、土間コン（㎡）、カーポート、物置、樹木（高さ別本数）、竹、庭石、浄化槽、井戸
- 残置物: 入居状況（カーテン・自転車・貼り紙）、屋外の残置物の量（㎥）、室外機台数
- アスベスト疑い: 外壁吹付材、スレート屋根・波板、軒天（ケイカル板）。築2006年以前は事前調査を必ず計上
- 施工条件: 前面道路の幅（重機・4t車が入るか）、隣地との離れ（50cm未満＝近接）、高低差、搬出距離 → `conditions`
  （キーは `data/demolition_unit_prices.json` の `condition_factor`）
- 高低差: 道路と敷地、隣地と敷地の段差（ブロック段数・メジャー）→ `site.existing.points` に「どこが何m」で入れる
- 写真ごとに、読み取った箇所を `photos[].marks[]` に bbox（画像に対する 0〜1 の比率 [x0,y0,x1,y1]）＋ラベルで残す。写真台帳に赤枠で描画される。

### 2. 公開データを取る（住所がある場合）
```
python .claude/skills/site-photo-report/scripts/run.py fetch jobs/.../site.json
```
- 住所→座標、国土地理院 1m/5m/10m DEM（敷地ローカル格子に変換して `site.existing.dem` に格納）、航空写真（`terrain/aerial.jpg`、地理院の上限 z18≒0.5m/px）、
  用途地域・建ぺい率・容積率・防火（国交省 都市計画決定GISデータ。参考情報）、近傍の地価公示・地価調査、ハザード（洪水・内水・高潮・津波・土砂・大規模盛土）、
  地形分類、J-SHIS（地震確率・表層地盤）、逆ジオコード → `land_info` に確実性付きで自動追記。初回は県別 zip をダウンロードするので数十秒かかる。
- 実取引価格（不動産情報ライブラリ）は API キーが必要なので取らない。
- **航空写真を Read で見て**、建物の外形・屋根形状・敷地形状・道路の位置・方位を確認し、写真からの推定と突き合わせる。住所の代表点が敷地からずれていたら `site.anchor_latlon` を敷地中心に直して再度 fetch。
- データ源の一覧と注意: `references/public_data_sources.md`

### 3. 法令・土地の情報
- 社内の法令チェックツール（MCP の `land_law_check` / `land_summary`）が使えるなら、住所と計画（解体後の建替え／分譲など）で呼び、用途地域・建ぺい率・容積率・接道・がけ条例・盛土規制法の区域などを `land_info` に入れる。
- 各項目に確実性（確定／要確認／推測）と出典を必ず付ける。DEM・写真からの値は「推測」。
- 相場・土地勘（地域の解体単価の傾向、周辺の造成の傾向、地価の水準）は分かる範囲で `market_notes` に。地域係数は `region`（`tokyo23` 等、キーは単価JSONの `region_factor`）。

### 4. site.json を埋める
スキーマは `examples/site.template.json`（コメント付き）。要点:
- `building`: 構造・階数・外形・軒高・戸数・付属物、`elevations`（4面。要素の種類は `scripts/sitekit/elevation.py` の冒頭）
  - 数量の精度のために `floor_plans`（階ごとの外形 w・d か area_m2。部分2階・下屋はここで表す）、`roof`（`pitch_sun` 寸勾配、`kind` 屋根材: kawara_dobuki/kawara/slate/metal/shingle/flat）、`foundation_type`（nuno/beta/dokuritsu）を入れる。外壁・屋根・基礎・廃材の数量と食い違いチェックは `scripts/sitekit/quantities.py`（係数は単価JSONの `quantity_rates`）
- `exterior`: 外構の数量（`key` は単価JSONの items キー）。`geom` を入れると現況平面図に描かれる
- `leftover`: 間取り・残置がある戸数・屋外残置物㎥・室外機台数
- `site`: 敷地境界（ローカル座標 m、x=東 y=北）、前面道路（edge・幅員）、`existing.points`（写真・実測の高さ）、
  `existing_buildings`（解体する建物の外形）、`plan`（計画高の決め方: `road_plus`＝道路境界最高点+0.3m が既定、`balance`＝切盛バランス、`fixed`）
- `summary`（表紙の要点 3〜6行）、`next_checks`（次に確認すること）

### 5. 出力して目視チェック
```
python .claude/skills/site-photo-report/scripts/run.py build jobs/.../site.json --out jobs/.../output
pdftoppm -r 50 -png jobs/.../output/<slug>.pdf /tmp/chk   # 各ページを Read で確認
```
- 文字の重なり・図のはみ出し・寸法の不整合（立面の幅と平面の外形、延床と戸数×専有面積）を確認して直す。
- 坪単価（諸経費込み）が構造別相場から大きく外れていないか、造成の擁壁高さが写真の段差と合っているかを確認。

### 6. 返答
1. 結論：解体概算（標準と幅）、造成概算（標準と幅）、合計
2. この敷地の要点（最大のリスク・費用が振れる要因）
3. 図面・資料の一覧（PDF／Excel／DXF）→ SendUserFile で送る
4. 精度の注意（推定値であること、正式には現地調査・測量・アスベスト調査・地盤調査）
5. 次に確認すること（追加写真・実測があれば精度が上がる箇所）

## 判断の基準（造成）
- 詳しくは `references/grading_knowledge.md`（造成計画図の作図ルール・盛土規制法/開発許可/がけ条例の判定・擁壁の選定・パターン別方針・土量計算）
- 計画高は「道路境界の最高点＋0.3m」を既定（雨水が道路側へ流れ、道路からの浸水を防ぐ）。切土が大きく残土が多い場合は `balance` と比較して安い方を `summary` に書く。
- 擁壁は境界ごとの最大段差で選定（`data/grading_unit_prices.json` の `wall_selection`）。高さ2m超はがけ条例・工作物確認、盛土1m超／切土2m超の崖は盛土規制法の許可対象の可能性として必ず表記。

## 判断の基準（解体）
- 詳しくは `references/demolition_costs.md`。建物単価は市場の坪単価（足場・養生・基礎撤去・廃材処分・簡易整地込み）。付帯・残置物・アスベスト・届出は別積み。
- アスベスト含有時の追加は合計に入れず別枠で示す（調査結果で増減するため）。

## やらないこと
- 推定値を確定値のように書かない（必ず「約」「推定」「参考値」）。
- 写真に写っていない地中（埋設物・古い基礎・浄化槽）を断定しない。可能性として `next_checks` に書く。
- 正式な見積・設計図書として出さない（参考資料。最終判断は現地調査・測量と建築士・施工業者）。
